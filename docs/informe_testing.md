## Casos de Prueba

- Definir la **configuración del entorno de pruebas**:
  - Dispositivos y/o sistemas operativos usados.
  - Navegadores probados.
  - Datos de prueba empleados.

- Presentar una tabla/listado de **casos de prueba** con:
  - Identificador (CP-01, CP-02, …).
  - Descripción.
  - Datos de entrada.
  - Pasos a seguir.
  - Resultado esperado.
  - Resultado obtenido.
- Asegurarse de incluir **casos de borde, errores y datos inválidos** (criterio de caja negra).

## Sesiones de Prueba Exploratoria

- Describir cada sesión de prueba realizada:
  - **Misión de la sesión** (ej: “probar la gestión de usuarios en dispositivos móviles”).
  - Tester responsable.
  - Tiempo/duración de la sesión.
  - Notas o hallazgos encontrados.
- Documentar varias sesiones distintas (profundidad y diversidad).
- Mostrar evidencias (capturas de pantalla, registros de pasos, etc.).

## Reporte de Issues

- Reportar los issues encontrados en GitHub u otra plataforma de seguimiento.
- Cada issue debe incluir:
  - Título claro.
  - Pasos de reproducción.
  - Resultado esperado vs. obtenido.
  - Clasificación por **tipo de problema** (bug, mejora, etc.) y **severidad** (crítico, mayor, menor).

- En el informe:
  - Incluir un **sumario** de issues (cantidad total y desglosada por tipo/severidad).
  - Referenciar con links los issues reportados.
